# Archiver: розумний захищений архіватор файлів

Командний семестровий проєкт 2 з дисципліни «Алгоритми і оптимізація програмних рішень».

Програма бере набір файлів і створює захищений архів: стиснутий, зашифрований, з контролем цілісності і розбиттям на томи заданого розміру. Розархіватор відновлює файли побайтово точно. Формат архіву задає `FORMAT_SPEC_P2.md` від викладача.

## Команда і зони відповідальності

| Зона | Відповідальний | Рівень |
| --- | --- | --- |
| Стиснення і розбір потоку (канонічний Гаффман, жадібний і лінивий LZ77) | Невінський Олександр | Базовий |
| Аналіз файлу і оптимізація (перцептрон, генетичний алгоритм) | Горбенко Семен | Базовий |
| Захист і пакування в томи (PBKDF2, AES-256-CTR, HMAC, рюкзак 0/1) | Кулик Ерік | Базовий |
| Інтеграція (формат, parser/writer, тракт, CI, вимір Q) | Шершень Артур | Базовий |

Зони і рівні зафіксовані на Зрізі 0 і далі не змінюються.

## Як запустити з нуля

Потрібен .NET SDK 8.0.

```
git clone <адреса репозиторію>
cd Archiver
dotnet restore
dotnet build -c Release
dotnet test -c Release
dotnet run --project src/Archiver.Cli
```

Команди `create` і `extract` з'являться на Чекпоінті 1 (тиждень 4).

## Як ми працюємо

- Кожен працює у своїй гілці (`feature/huffman`, `feature/classifier`, `feature/crypto`, `feature/format`). Напряму в `main` не комітимо.
- Кожен коміт прив'язаний до issue (наприклад `Refs #12: canonical Huffman code lengths`).
- Зміни потрапляють у `main` через pull request, який переглядає хтось інший із команди.
- Кожен алгоритм спочатку тестується окремо, потім у зв'язці. Після кожного етапу запускаємо весь набір тестів.
- Рішення, які ми обговорювали, записуємо в `docs/DECISIONS.md`.
- Використання ШІ фіксуємо в `META-USAGE.md` одразу, а не наприкінці семестру.

## Правила проєкту, які ми не порушуємо

- Гаффман, LZ77, ДП, перцептрон і ГА пишемо самі. Бібліотеки дозволені лише для AES, SHA-256, роботи з файлами, графіків і тестів.
- `GZipStream`, `DeflateStream` та аналоги можна викликати тільки як еталон для порівняння, з явною позначкою в коді і звіті, не в тракті архіватора.
- Криптографічні параметри (PBKDF2, 100 000 ітерацій, сіль 16 байт, K_enc і K_mac, AES-256-CTR, HMAC-SHA256) беремо з `FORMAT_SPEC_P2.md`, не вигадуємо.
